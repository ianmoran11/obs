Compositional Stochastic Systems

A teaching companion to the obs-teach Lean simulator.

This book accompanies a small Lean 4 microsimulator that models a synthetic cohort of Australians moving through three life lenses — labour, education, and justice — over a substrate of demographic Person records. The simulator is deliberately tiny; the point is to exhibit, in code, every structural concept the course introduces. This book sits beside the source and tells you what each piece is and why it has the shape it does.

The course it follows runs in eleven modules. Each chapter here corresponds to one module and ends with a callout pointing at the Lean file that implements the concept. If you want to read the book linearly, you can; if you want to dive into the simulator and only consult the book when something is unclear, the cross- references make that easy.

How to read

Three styles of writing appear together:

  • Narrative prose. Plain English. The narrative explains why the concept is shaped the way it is.
  • Mathematical notation. Standard category-theory and probability notation, rendered with MathJax. Things like $\mathrm{Tr}^X(f) : A \to B$ and $f^\dagger_p \circ \mathrm{copy}_Y \circ (f \circ p) = \mathrm{copy}_X \circ p$.
  • Code excerpts. Short snippets from the Lean source, with file names. The full files live under ../ObsTeach/.

Diagrams appear inline when they help. They are intentionally sparse — most string-diagram intuition is more useful when you draw it yourself than when someone draws it for you.

Conventions

Categories: $\mathcal{C}$, $\mathbf{Set}$, $\mathbf{FinStoch}$, $\mathbf{Poly}$, $\mathbf{Para}(\mathcal{C})$.
Polynomials: $p$, $q$ — with positions $p_{\text{pos}}$ and direction sets $p[i]$ for $i \in p_{\text{pos}}$.
Stochastic morphisms: $f : X \to \mathcal{D}(Y)$ for the discrete Giry monad $\mathcal{D}$.
Lenses: a lens between polynomials has a forward map of positions and a backward map of directions; we will draw and write this many times.

Module 1Polynomial coalgebras

State machines whose interfaces are typed.

A polynomial coalgebra is a state machine whose outgoing transitions at each state are typed by a position-dependent set of labels. It is the structural skeleton on which everything else hangs.

Fix a category $\mathcal{C}$ with finite products and coproducts. A polynomial functor on $\mathcal{C}$ is

$$ p(X) \;=\; \sum_{i \in p_{\text{pos}}} X^{p[i]} $$

where $p_{\text{pos}}$ is a set of positions and $p[i]$ is the set of directions at position $i$. Read $p(X)$ as: "for some position $i$, pick an $X$-value for each direction out of $i$". An $F$-coalgebra is a morphism $c : S \to F(S)$. When $F = p$ for a polynomial $p$, an $S$-state coalgebra produces a position $i$ and an $S$-value per direction $d \in p[i]$. The simulator's per-lens dynamics is exactly this.

The directions are the multinomial outcomes the calibration step will later estimate. Choosing one is what every per-period draw does. Choosing one stochastically is what the next module's Markov-category lift achieves.

Module 2Yoneda & representables

Why a lens between polynomials is “exactly” the right shape.

A polynomial $p$ is a coproduct of representable functors. The Yoneda lemma says natural transformations out of representables are just elements of the target functor. Together: a morphism between polynomials is exactly a forward map of positions plus a backward map of directions.

For a category $\mathcal{C}$ and an object $A$, the representable functor is $h^A = \mathcal{C}(A, -) : \mathcal{C} \to \mathbf{Set}$. The Yoneda lemma says, for any functor $F$:

$$ \mathbf{Nat}(h^A, F) \;\cong\; F(A) $$

A natural transformation out of a representable is just a single element of the target functor's value at $A$. A polynomial functor $p(X) = \sum_i X^{p[i]}$ is a coproduct of representables $X^{p[i]} = h^{p[i]}(X)$, so a natural transformation $p \Rightarrow q$ is, for each position $i$ of $p$, an element of $q(p[i]) = \sum_j (p[i])^{q[j]}$. Unpacking that coproduct: a position $j$ in $q$ plus a function $q[j] \to p[i]$ on the directions.

That is the data of a lens between polynomials:

  • Forward: $\varphi : p_{\text{pos}} \to q_{\text{pos}}$ — every position of $p$ knows which position of $q$ it presents.
  • Backward: $\varphi^\sharp : (i : p_{\text{pos}}) \to q[\varphi(i)] \to p[i]$ — a direction in the outer (post-)position routes to a direction in the inner (pre-)position.

The forward leg is “simulate”; the backward leg is, in the parametric setting we'll meet next, “update”. The Yoneda lemma is what guarantees these are the only two pieces of data you need.

How this lives in the code

structure PolyLens (p q : Polynomial) where
  fwd : p.Pos → q.Pos
  bwd : (i : p.Pos) → q.Dir (fwd i) → p.Dir i

Found in ObsTeach/Foundations.lean. Every parametric lens we construct in ObsTeach/ParaLens.lean derives its forward/backward shape from this Yoneda decomposition.

Module 3Parametric lenses

Forward = simulate, backward = update.

A parametric lens is a lens whose backward leg threads parameters as well as directions. The forward leg is the simulator's per-step morphism; the backward leg is calibration. Both halves live in the same typed shape.

The Para construction turns a monoidal category $\mathcal{C}$ with a chosen parameter object $\Theta$ into a new category whose morphisms $X \to Y$ are morphisms $\Theta \otimes X \to Y$ in $\mathcal{C}$. Composition threads $\Theta$ through both:

$$ (\Theta \otimes Y \xrightarrow{g} Z)\circ_{\mathrm{Para}}(\Theta \otimes X \xrightarrow{f} Y) \;=\; \Theta \otimes X \xrightarrow{(\mathrm{copy}_\Theta \otimes \mathrm{id}_X)} \Theta \otimes \Theta \otimes X \xrightarrow{\mathrm{id}_\Theta \otimes f} \Theta \otimes Y \xrightarrow{g} Z $$

What makes this useful is that the same shape describes the simulator's forward step (sample a transition given parameters) and its calibration (update parameters given an observation). The two halves compose cleanly because they are both morphisms of $\mathbf{Para}$.

Module 4Markov categories & rate kernels

Stochastic dynamics, rates, hazards.

A Markov category is a symmetric monoidal category with a copy and a discard, where discard is natural in every morphism. Inside it, a rate kernel is the canonical form of every transition in the simulator.

A Markov category $(\mathcal{C}, \otimes, I, \mathrm{copy}, \mathrm{del})$ is a symmetric monoidal category with, for every object $X$, a comultiplication $\mathrm{copy}_X : X \to X \otimes X$ and a counit $\mathrm{del}_X : X \to I$, satisfying commutative-comonoid laws and the crucial naturality:

$$ \mathrm{del}_Y \circ f \;=\; \mathrm{del}_X \quad \text{for every } f : X \to Y. $$

Reading: discarding the output of $f$ is the same as not running $f$. In probabilistic terms, this is normalisation. The morphisms for which $\mathrm{copy}$ is also natural are exactly the deterministic ones — this gives a categorical definition of "deterministic" inside a stochastic setting.

For our simulator the relevant Markov category is $\mathbf{FinStoch}$ — finite sets with stochastic matrices as morphisms. A transition kernel from state $i$ to state $j$ is a stochastic matrix $P[i,j] \in [0, 1]$ with $\sum_j P[i,j] = 1$.

Rate kernels and CTMCs

A discrete-time Markov chain is a coalgebra of $\mathcal{D}$ (the distribution monad), but discrete-time parameters are tied to a chosen tick width. Calibration shouldn't have to be redone every time you change the tick. The fix is to drop down to rates. A continuous-time Markov chain (CTMC) is parameterised by a rate matrix $Q$ with

$$ Q[i, j] \geq 0 \quad (i \neq j), \qquad Q[i, i] \;=\; -\!\!\!\sum_{j \neq i} Q[i, j]. $$

Given $Q$, the per-tick transition matrix at width $\Delta t$ is the matrix exponential

$$ P(\Delta t) \;=\; \exp(Q \Delta t) \;=\; I + Q \Delta t + \tfrac{(Q \Delta t)^2}{2!} + \dots $$

And $P(\Delta t_1) P(\Delta t_2) = P(\Delta t_1 + \Delta t_2)$ — quarterly iterated four times equals annual, automatically. We never compute this exponential at runtime in the demo: we sample directly in event time using competing exponentials:

Hazard models for non-memoryless states

The exponential is memoryless: $\Pr(T > t + s \mid T > s) = \Pr(T > t)$. Fine for radioactive decay; wrong for prison sentences, which empirically have a length. We replace the constant rate with a hazard $\lambda(\tau)$ depending on time-in-state $\tau$. For our prison stay we use a Weibull hazard with shape $k$ and scale $\eta$:

$$ \lambda(\tau) \;=\; \frac{k}{\eta} \left(\frac{\tau}{\eta}\right)^{k-1} $$

Sampling is by inverse-CDF; competing risks generalises to "draw a time per direction with its own hazard, take the minimum". The architecture changes by one column on the per-person record — time_entered_state.

Module 5Categorical Bayes

Inversion, conjugacy, naturality.

Bayes’ rule is a categorical operation. In a Markov category, the Bayesian inverse of a likelihood given a prior is the morphism that makes both ways of constructing the joint distribution agree.

Fix a Markov category $\mathcal{C}$, a prior $p : I \to X$, and a likelihood $f : X \to Y$. The joint is

$$ \mathrm{joint}_{p, f} \;=\; (\mathrm{id}_X \otimes f) \circ \mathrm{copy}_X \circ p \;:\; I \to X \otimes Y. $$

A Bayesian inverse $f^\dagger_p : Y \to X$ relative to $p$ is the morphism (when it exists) such that

$$ (f^\dagger_p \otimes \mathrm{id}_Y) \circ \mathrm{copy}_Y \circ (f \circ p) \;=\; (\mathrm{id}_X \otimes f) \circ \mathrm{copy}_X \circ p. $$

Conjugacy

A prior family $\{P_\xi\}_{\xi \in \Xi}$ is conjugate to a likelihood when the posterior stays in the family: there is an update map $u : \Xi \times D \to \Xi$ with $f^\dagger_{P_\xi}(d) = P_{u(\xi, d)}$. The Bayesian inverse collapses to an endomorphism on $\Xi$.

For our simulator the relevant pair is Dirichlet–Multinomial. The likelihood is multinomial on $K$ outcomes; the prior is $\mathrm{Dirichlet}(\alpha)$ for $\alpha \in \mathbb{R}^K_{>0}$; observing a count vector $n = (n_1, \dots, n_K)$ gives

$$ \theta \mid n \;\sim\; \mathrm{Dirichlet}(\alpha + n). $$

The update is componentwise addition. That's it. Posterior summaries:

$$ \mathbb{E}[\theta_k \mid n] \;=\; \frac{\alpha_k + n_k}{\sum_j (\alpha_j + n_j)}, \qquad \mathrm{MAP}_k \;=\; \frac{\alpha_k + n_k - 1}{\sum_j (\alpha_j + n_j - 1)}. $$

With $\alpha = (\tfrac12, \dots, \tfrac12)$ (Jeffreys) and posterior mean, this is the BLUEPRINT §5.1 estimator. With $\alpha = (1, \dots, 1)$ and the mode, it is the frequentist MLE.

Naturality

The update is natural in the data: sequential and batch updates agree.

$$ u(u(\xi, d_1), d_2) \;=\; u(\xi, (d_1, d_2)). $$

For Dirichlet this is associativity of $\mathbb{R}^K$ addition. The categorical content is that the modular calibration architecture — per- cell, per-period, possibly across data sources — is sound.

How this lives in the code

def update (α : Dirichlet) (counts : Array (String × Nat)) : Dirichlet :=
  α.map fun (d, x) =>
    let n := (counts.find? (·.1 = d)).map (·.2) |>.getD 0
    (d, x + n.toFloat)

def fromCounts (directions : Array String) (counts : Array (String × Nat)) : Dirichlet :=
  let prior : Dirichlet := directions.map (fun d => (d, 0.5))
  update prior counts

Module 6The additive trace

Within-period dynamics as a feedback loop with a side accumulator.

The events table is the accumulator value of an additive trace. The DuckDB GROUP BY queries that compute per-period summaries are folds over that accumulator.

The categorical trace closes a feedback loop. Given a morphism $f : A \otimes X \to B \otimes X$ in a traced monoidal category, $\mathrm{Tr}^X(f) : A \to B$ is the morphism you get by routing the $X$ output back to the $X$ input.

The plain trace throws away iterations. We want to keep them. The additive trace augments $f$ with an output in a commutative monoid $M$:

$$ f \;:\; A \otimes X \to B \otimes X \otimes M, \qquad \mathrm{Tr}^X_{\oplus M}(f) \;:\; A \to B \otimes M. $$

Each iteration contributes an element of $M$; iterations combine by the monoid product. For the simulator $M$ is the bag of events — multisets of (person, period, time, lens, from, direction) rows under multiset union. That bag is the events table.

The BLUEPRINT four-function interface decomposes as:

  • draw — the iteration step $f$.
  • split — the halt predicate (period end or lens exit).
  • accumulate — the monoid multiplication.
  • emit — the projection to per-period observables. In DuckDB, this is a GROUP BY.

How this lives in the code

structure Event where
  personId   : Nat
  period     : Nat
  time       : Float
  lens       : String
  fromState  : String
  direction  : String

partial def runWithinPeriod ... :=
  let rec loop (cur : String) (now : Float) (s : RandState) (acc : Array Event) :=
    let (eventTime, direction, s') := draw key now s
    if eventTime ≥ periodEnd then (acc, cur, periodEnd, s')
    else loop (transition cur direction) eventTime s' (acc.push event)

Module 7Wirings (double categories)

Cross-lens constraints as backward legs of wiring lenses.

A double category has two perpendicular kinds of arrow. Horizontal arrows wire systems together; vertical arrows swap an implementation while preserving the interface. The two-cell coherence says these axes commute.

The double category $\mathbf{Sys}$ of systems (Libkind & Myers) has:

  • Objects — interfaces (polynomials).
  • Horizontal arrows — wirings; lenses out of the parallel composite of inner systems into a refined outer interface.
  • Vertical arrows — behaviour-preserving morphisms (discretisation, hazard-wrapping, carrier coarsening).
  • 2-cells — coherence squares saying the two operations don't interfere.

The wirings in our demo are pairwise functions from joint inner state to joint outer state. Their backward leg decomposes one outer event into coordinated inner events:

The vertical arrows we use are: the Discretise(\Delta t) operator on rate kernels (Module 4), the hazard wrap on the prison position, and the cell coarsening $\mathrm{Person} \to \mathrm{cell}$ that groups people into the calibration GROUP-BY's covariate cells.

def wireJusticeToLabour (oldJ newJ : JusticeState) (l : LabourState) : LabourState :=
  match oldJ, newJ with
  | _, .imprisoned     => .nilf

Module 8Substrate as fibration

Person is the base, every lens is a fibre.

Every lens reads the substrate. Only Population writes to it. Categorically: the joint state is the Grothendieck construction of a Person-indexed family of per-lens fibres.

A fibration $p : \mathcal{E} \to \mathcal{B}$ is a functor with a cartesian-lifting structure. For each base object $b$ the fibre $\mathcal{E}_b = p^{-1}(b)$ is a category in its own right. The Grothendieck correspondence equates fibrations over $\mathcal{B}$ with pseudofunctors $F : \mathcal{B}^{\mathrm{op}} \to \mathbf{Cat}$.

The dual perspective: every domain-lens kernel is a co-Kleisli morphism in the Reader comonad on Person. It takes Person as context and produces a transition without modifying the Person record. Population's kernel is the only one that doesn't factor through Reader — it writes to Person itself.

The substrate theorem: in the slice category $\mathbf{Set}/\mathrm{Person}$, the Population lens corresponds to $\mathrm{id}_{\mathrm{Person}}$, and every domain lens admits a unique slice-morphism into it given by the projection from per-lens state down to person.

Module 9Marginal-schema olog

A common ground that lets multiple sources contribute to one posterior.

An olog is a categorical schema. A schema morphism is a functor between schemas. Functorial data migration moves data along it. The marginal-schema olog is the schema that simulator events and external empirical rows share — the common ground of calibration.

Following Spivak, a schema is a (small) category. An instance is a functor from the schema into $\mathbf{Set}$. A schema morphism is a functor $\Phi : T \to S$. Three associated migration functors move instances along it:

  • $\Delta_\Phi$ — pullback (precompose). The cheapest migration; just rename columns.
  • $\Sigma_\Phi$ — left Kan extension. Aggregate / disjoint-union.
  • $\Pi_\Phi$ — right Kan extension. Tuple / product-aggregate.

The simulator's events table $S_{\text{sim}}$ admits a morphism $\Phi : M \to S_{\text{sim}}$ (in the right direction for $\Delta$-migration). External empirical tables $S_{\text{emp}}$ admit a morphism $\Psi : M \to S_{\text{emp}}$. Both can be pulled back to $M$. The calibration query consumes $M$-shaped rows uniformly.

Module 10Calibration as backward leg

A single function: events → posterior.

Calibration is the backward leg of the parametric lens framework. In the conjugate Dirichlet–Multinomial setting it is one GROUP BY plus addition. The same function fits both the round-trip recovery and the cross-source calibration.

The categorical type signature is

$$ \mathrm{calibrate} \;:\; \text{events} \longrightarrow \mathrm{Calibrated} \;=\; \text{KernelKey} \to \mathrm{Dirichlet}. $$

where a KernelKey is a (cell, lens, from-state) triple. The function's body is three steps:

  1. Project events to MarginalRows with $\mathrm{count} = 1$ each (Module 9 schema morphism).
  2. Aggregate by key, summing counts (the GROUP BY).
  3. For each key, build the Dirichlet posterior under the Jeffreys prior $\alpha = (\tfrac12, \dots, \tfrac12)$ via componentwise addition (Module 5 conjugate update).

The architecture supports two flavours of summary:

  • Posterior mean: $\hat\theta_k = (n_k + \tfrac12) / \sum_j (n_j + \tfrac12)$. The Bayes-Laplace estimator. Default in the demo.
  • Posterior mode with $\alpha = (1, \dots, 1)$: $\hat\theta_k = n_k / \sum_j n_j$. The frequentist MLE. One-line change.

Cross-source calibration is the same function applied to the concatenation of simulator-derived rows and external empirical rows. The marginal-schema olog (Module 9) is what makes both row sources compatible.

How this lives in the code

def calibrateFromRows
    (rows : Array MarginalRow)
    (directionsOf : KernelKey → Array String) : Calibrated := Id.run do
  let agg := aggregate rows
  let mut grouped : Std.HashMap KernelKey (Array (String × Nat)) := {}
  for r in agg do
    let k : KernelKey := ⟨r.cell, r.lens, r.fromState⟩
    let curr := (grouped[k]?).getD #[]
    grouped := grouped.insert k (curr.push (r.direction, r.count))
  let mut result : Calibrated := {}
  for entry in grouped.toArray do
    let k := entry.1
    let dirs := directionsOf k
    let post := fromCounts dirs entry.2
    result := result.insert k post
  pure result

ObsTeach/Calibration.lean. The structure of this function is exactly the structure of the BLUEPRINT §5.1 SQL query: a GROUP BY, plus an alpha-smoothed normalisation.

Module 11Capstone

Every previous module, in one driver.

The simulator's main loop is the categorical pipeline of every module that came before. Reading the loop top-to-bottom is reading the course in order.

Top-level shape of the driver:

def runSimulation (cfg : Config) : (Array Event × Array JointState) := Id.run do
  let cohort := initCohort cfg.numPersons       -- Module 8: substrate
  let mut states : Array JointState := cohort.map initJoint
  let mut events : Array Event := #[]
  let mut s : RandState := cfg.seed             -- Module 4: PRNG
  for period in [0 : cfg.numPeriods] do
    for st in states do
      let (evts, st', s') :=
        runPersonPeriod period periodStart periodEnd st seed
                                                -- Module 6: additive trace
                                                -- Module 4: rate kernels + Weibull
                                                -- Module 7: cross-lens wirings
      events := events ++ evts
    states := ageCohort cfg.dtYears newStates   -- Module 8: Population kernel
  pure (events, states)
